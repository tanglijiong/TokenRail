# M5.1：崩溃、部署身份与账务时间

## 租约为什么还需要版本

`PROCESSING` 只说明任务被领取，不说明领取它的进程还活着。每次领取递增 `claim_version`，并设置 `lease_until`。过期任务可以由其他 worker 重新领取；每次签名落库、状态转换和经济记账都在同一个短数据库事务内锁定任务并检查版本、期限和部署状态。旧 worker 不能用旧版本释放预留存款或覆盖新结果。

数据库行锁不包裹 RPC。nonce 分配和签名原文分别持久化；广播前已有交易 hash。恢复时先查原 hash，必要时重新广播同一份签名原文，而不是重新分配 nonce。即使原交易已经上链、数据库还没有记录广播结果，也只产生一次经济效果。

## chainId 不能识别重置后的环境

`chainId` 是签名域的一部分，不是数据库部署主键。服务同时检查 genesis hash、部署区块锚点和投影 checkpoint；身份不一致时停止处理，确定的 hash 冲突会将部署标为停用。RPC 暂时不可用只阻止本轮处理，不自动重写部署身份。

部署 manifest 的 ID 还包含每次部署的新随机值。相同 genesis、相同账户和相同部署交易不能导致不同运行共用 ID。账户、预留金额、backing、凭证、幂等请求、nonce、任务、投影均按部署隔离。交易目标通过数据库外键绑定部署记录。

链检查和发送 RPC 是两个动作；本阶段验证的是运行时检查及失败后隔离，不声称能将外部节点重置与交易提交做成跨系统原子操作。

## 银行账与链上余额的时间不同

对账在一次 PostgreSQL `REPEATABLE READ` 快照内固定 H、持仓、当前 backing 和业务分录，然后释放数据库事务再查询链。每份报告保存其实际使用的金额证据。

```text
H 的 backing = 快照中的已入账 backing
             - 已入账但链上发生在 H 之后的净分录
             + H 及以前已 mint、尚未转入 backing 的金额
             - H 及以前已 burn、尚未扣减 backing 的金额
```

已入账但发生在 H 之后的赎回是负的净分录。未知 receipt 不能被当成成功；已有银行分录却无法读取对应成功 receipt 时，对账返回 `SNAPSHOT_UNAVAILABLE`。测试不通过对齐 backing 到 totalSupply 来制造 MATCH。M4/M5 测试清库后链上仍保留过去发行，因此对应历史基础测试可以存在真实 backing 差异；完整 MATCH 验收使用独立的新链与数据库。

## 重建和差异关闭的边界

重建使用 `BUILDING` 版本；旧 ACTIVE 继续服务读取。每块提交余额、历史快照和 block hash。恢复沿用同一后台任务对应的版本。校验钱包余额与资产总量后，在短事务中原子切换 ACTIVE；与实时索引竞争时不会切换到更旧的水位。

持仓对账的钱包集合来自参与者、原始事件和快照，不只来自尚存的持仓行。另对每种资产检查持仓总量，避免删除一整行后检查也跟着消失。零金额与自转账保留原始事件，但不要求不存在的发送方持仓被扣减。

新高度的 MATCH 不能证明旧高度的错误已修复。差异关闭要求 deployment、block number/hash、检查类型、钱包和资产均与匹配证据一致。即使报告中仍有其他差异，已经逐项复核成功的差异也可关闭，并保留解决报告 ID。

## 如何复现

- `scripts/test-m5-projection.sh`：PostgreSQL + 四节点 Besu 的 8 项基础回归。
- `scripts/test-m51-reliability.sh`：独立 Anvil 端口、随机运行目录、新数据库；8 项可靠性测试，含真正终止 Java 子进程和真正 `anvil_reset`。

后一脚本需要前者启动的 PostgreSQL，默认容器名为 `tokenrail-m3-postgres-1`，可用 `TOKENRAIL_TEST_POSTGRES_CONTAINER` 修改；默认独立 RPC 端口为 18545，可用 `TOKENRAIL_M51_PORT` 修改。日志与 `.evidence` 保存到输出的运行目录。退出时只停止本次 Anvil，数据库保留供核查；不要把包含 `.key` 的整个运行目录公开上传。

真实链重置验收针对独立 Anvil；不是四节点 Besu 数据卷销毁测试。历史状态不可读的受控测试仍使用故障注入；不将其写成已完成节点裁剪实验。CI 已接入两组脚本，远程运行结果以 Actions 为准。
