# 学习记录

每个主题在实际实验后写一页，记录自己的理解和实际证据，不预填“已掌握”。

| 阶段 | 主题 | 必须能够回答 |
|---|---|---|
| M0 | 区块、交易与 EVM | 调用、广播、执行、receipt 有什么区别？失败交易为什么仍有 nonce / gas 影响？ |
| M0 | 私钥与签名 | 地址怎样得到？签名证明了什么？知道地址能否授权转移？ |
| M1 | ERC20 | balance、allowance、mint、burn 各改变什么？decimals 是什么？ |
| M1 | 存款代币 | 发行行负债怎样在本模型表达？为何普通存款不能同时保持可用？ |
| M2 | [DvP](03-atomic-dvp.md) | 为何两次 transferFrom 必须在同一次调用中？数据库事务能覆盖链吗？ |
| M2 | [授权](03-atomic-dvp.md) | 有 allowance 为什么仍需双方确认条款？谁能更改收款方？ |
| M3 | [许可网络与 QBFT](04-qbft-and-permissioning.md) | 节点许可、账户许可与 Token 准入有什么区别？四节点失去两个为什么停块？ |
| M4 | Java 与 EVM | RPC 超时后怎样找到原交易？为什么不能直接发新 mint？ |
| M5 | 事件与对账 | 投影为何仍需对账？如何区分延迟和真实差异？为何必须同区块？ |
| M5.1 | [可靠性边界](07-reliability-boundaries.md) | 旧 worker 为什么不能继续记账？历史对账怎样处理在途金额？ |
| M6 | [条件支付与业务编排](08-business-orchestration-and-escrow.md) | 谁声明条件成立？被冻结的钱怎样处理？链上不能证明什么？ |

单页记录结构：

1. 用自己的话解释它是什么、为什么需要。
2. 对应 TokenRail 的哪个入口、状态或不变量。
3. 与传统 Java / 银行业务概念的类比，以及类比失效的地方。
4. 本次自己执行的操作、结果与证据位置。
5. 一个故意失败案例和原因。
6. 一个面试问题及自己的回答，另列尚不理解的问题。

毕业演示：不用文档，画出一次 DvP 从双方确认、授权、签名到链上执行和链下投影的全过程；解释第二腿失败、RPC 超时、索引中断三类错误为何要采用不同处理。
