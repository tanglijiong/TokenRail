# M5.1 可靠性补齐

状态：R01–R07 已实现并通过本地验收，确认 v0.1-core。8 项 Besu 基础回归与 8 项独立可靠性测试通过；CI 已接入，未宣称远程运行通过。详细证据与限制见 [验收记录](evidence/m51-reliability-20260914/README.md)。

## 目标与范围

补齐真实进程崩溃、链重置、在途账务、并发重建和接口权限的恢复边界。已有测试结果保留为基础证据，不等同于完整可靠性验收。本阶段不增加 PaymentEscrow 或前端；DvP 的完整业务 API 在 M6 接入界面前完成。

## 关键实现约束

- 数据库迁移采用新增版本，不改已应用的 V1/V2；保留既有业务分录。
- RPC 不置于数据库持锁事务中；签名原文广播前持久化，未知状态先按原 hash 查证。
- 租约恢复必须阻止失去租约的 worker 提交过期结果；不能仅把 PROCESSING 批量改回 PENDING。
- 链身份检查覆盖服务启动和后续处理；genesis、部署身份及 checkpoint 共同识别环境。
- 对账中的 supply、持仓、backing 及在途金额必须具有可解释的同一区块口径；不通过测试代码改 backing 来制造 MATCH。
- 新版本重建不触发普通存款经济动作；切换前不把不完整版本当成当前完成投影。
- 测试清库、损坏数据及故障开关移入测试代码或明确的本地演示配置，不进入普通业务入口。
